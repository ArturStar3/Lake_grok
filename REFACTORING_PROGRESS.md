# Рефакторинг InfoLake: первая волна

Дата: 2026-10-01. Основание: [REFACTORING_PLAN.md](REFACTORING_PLAN.md), этапы 0–3 и раннее исправление нулевых значений из R11. Это отчёт о выполненной части, не объявление о завершении всех 25 пунктов программы.

Дополнительно исправлен локальный снимок дочерней записи при анализе импорта: ранее мог использоваться undefined либо снимок предыдущей сущности. SVG-обогащение меняет DOM-атрибуты вместо интерполяции строк; устраняет повторный xmlns, учитывает полный исходник в cache key и ограничивает содержимое кэша 32 MiB (оценка UTF-16, без накладных расходов объектов).

## Совместимость и эксплуатация

- Сохранены API routes, сериализованные поля, формат bundle v1, имена media-путей, map-layer IDs, same-origin/direct URL-модель. Небезопасные архивы/SVG и доступ к чужим сессиям намеренно отвергаются.
- Новая политика отображения разрешает русские тексты, таблицы, локальные картинки, статические SVG, внутренние gradients/clip paths. Скрипты, foreignObject, обработчики событий, внешние SVG-ресурсы и глобальный CSS запрещены. Простые class/id SVG-стили преобразуются в inline; editor metadata удаляется.
- Лимиты настраиваются через `backend/.env`; безопасные значения добавлены только в `backend/.env.example`. Значения настоящих секретов не менялись и не выводились.
- Модели и миграции в этой волне не изменялись; рабочая БД не мигрировалась. Новые зависимости и интернет-зависимости runtime не добавлялись.
- Новый updater требует новый checksummed пакет, чистую ветку production и работающую текущую установку. Он не предназначен для первой установки или перехода между режимами. См. обновлённый раздел 9 в [PRODUCTION_LAUNCH.md](PRODUCTION_LAUNCH.md).
- До начала работы уже существовала большая декомпозиция API/demo/map и другие изменённые/удалённые/неотслеживаемые файлы. Они сохранены, не считаются результатом этой волны и не были автоматически закоммичены.

## Выполненные проверки

Финальные результаты после завершения правок приведены ниже. Команды backend выполняются в уже работающем контейнере, источник `/app` смонтирован из текущего `backend/`.

- `python manage.py check`: без ошибок.
- Полный `python manage.py test --verbosity=1`: 131 тест, включая 31 новый тест импорта/рендеринга; все проходят.
- `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/production/test-update-policy.ps1`: 35 проверок. Синтаксис PowerShell, modes/images, hashes, backup failure/empty/checksum, аргументы offline startup, нестандартные proxied/direct порты, запрет recovery после возможной миграции. Docker/Git в этих policy-тестах замоканы; интеграционные операции не выполняются.
- `npm.cmd run lint`: 0 ошибок, 85 существовавших предупреждений.
- `npm.cmd run build -- --outDir <новая временная папка>`: успешно; существующий frontend/dist не перезаписывается. Предупреждение о размере основного JS chunk остаётся; оптимизация R18 ещё впереди.
- `node tileserver/scripts/build-unified-style.js --check`: текущий стиль/mapping совпадают с источниками; файлы не изменены.
- Compose `prod` и `direct-prod`: `config --quiet` успешно. `prod_postgres` не проверен с настоящими настройками: в root `.env` отсутствует требуемый POSTGRES_PASSWORD; значение не запрашивалось и не добавлялось.
- Diff просмотрен. Единственная ошибка общего `git diff --check` — ранее существовавшая пустая строка в `backend/api/views.py:67`; этот пользовательский файл не исправлялся в рамках волны.

## Что осталось

1. Перед выпуском: ревью и оформление владельцем всех исходных пользовательских изменений, потом сборка нового пакета с чистого production SHA. Автоматическое коммитирование/переключение ветки не выполнялось.
2. Отдельный PostgreSQL-стенд: concurrent apply/cancel, отказ миграции, восстановление backup на новой БД, запуск предыдущей согласованной версии. Проверить update/recovery во всех поддерживаемых режимах и нестандартные порты.
3. Браузерная регрессия: старые маркеры/флаги/палитры, SVG preview, нулевые координаты, local images в отчётах, обычный большой bundle.
4. Этапы 4–9 остаются открытыми: auth/cache/rate-limit, ревизии и constraints, workflow/editor decomposition, demo playback, производительность/export streaming/conflict pagination/LOS, остальные build/config/docs/converter-задачи. Точечные улучшения выше не закрывают эти этапы целиком.

Готовность первой волны: код и перечисленные автоматические проверки готовы к review; production-приёмка и полная программа не завершены.
